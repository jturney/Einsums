# psi4 plugin template: einsums stages in two sealed binaries

The hybrid framework's host-integration pattern, worked as a real psi4 plugin.
`hybrid_mp2/` computes the RHF MP2 correlation energy with the integrals transformed in the psi4 world and the numerics run as an einsums stage, on either backend.
To start a method of your own, copy the package, rename `hybrid_mp2` throughout, and replace the physics; every structural decision worth keeping is written at the top of the file it lives in.

## The rule the template enforces by construction

A psi4 plugin that wants C++ stages ships **two** binaries:

| binary | world | links | built by |
| --- | --- | --- | --- |
| `hybrid_mp2.so` | psi4 | psi4 only | `hybrid_mp2/CMakeLists.txt` |
| `hybrid_mp2_stages.so` | Einsums | Einsums only | `hybrid_mp2/cpp/CMakeLists.txt` (generated by promote) |

One binary linking both is forbidden by the sealed-worlds rule.
The two meet only in the plugin's Python, and only buffers cross: the psi4-world binary leaves plain Matrices on the wavefunction, the adapter copies them into a host-free dataclass, and the stage sees einsums tensors.
`otool -L` (or `ldd`) on either binary is the audit: the plugin references psi4's `core` and no `libEinsums`; the stage module references `libEinsums-abi1` and no psi4.

The rule constrains what each target links, not how many builds you run: both binaries come out of **one configure and one build**, because `hybrid_mp2/CMakeLists.txt` adds the promote-generated `cpp/` as a subdirectory.
Sharing one build tree means sharing one toolchain, and psi4's plugin cache pins the same conda compilers the Einsums dev environment documents, so that is the supported path.
A psi4 built with a foreign toolchain is the one case that splits the builds again: configure `cpp/` standalone (its `CMakeLists.txt` documents how), and let the import-time fingerprint handshake be the backstop.

## Layout

```
hybrid_mp2/
  __init__.py       psi4 plugin init; the driver half loads only if psi4 is importable
  pymodule.py       driver: SCF -> plugin .so -> adapter -> stage -> psi4 variables
  plugin.cc         psi4-world binary: MO (ia|jb) via MintsHelper, left on the wfn
  CMakeLists.txt    psi4-world build (add_psi4_plugin)
  reference.py      the method's true input: a host-free dataclass of plain arrays
  adapter.py        psi4 -> Reference; the ONE module that imports the host
  contracts.py      @contract return types, validated at import
  mp2.py            plan / numerics / finish; the numerics is the promotable stage
  stages.py         @stage declarations; what promote reads
  input.dat         example input, both backends compared against psi4's own MP2
  cpp/              generated by promote; only src/Mp2Energy.cpp's body is hand-written
```

The method half (`reference.py`, `contracts.py`, `mp2.py`, `stages.py`) never imports psi4, so `promote` and the differential test under `cpp/tests/` run in an environment with no psi4 at all.
That is the host-integration rule made structural rather than aspirational.

## Build and run

Everything below assumes the einsums conda dev environment is active; both worlds build with its toolchain and its Python, and a stage module built for a different CPython simply fails to import.

1. **An installed Einsums** (once):

   ```bash
   cmake --install /path/to/Einsums/build --prefix /tmp/einsums-install
   ```

2. **Both binaries, one configure**, with psi4's own plugin toolchain cache:

   ```bash
   cd hybrid_mp2
   cmake -S . -B build -GNinja \
     -C /path/to/psi4/stage/share/cmake/psi4/psi4PluginCache.cmake \
     "-DCMAKE_PREFIX_PATH=/path/to/psi4/stage;/tmp/einsums-install"
   cmake --build build
   ```

   This produces `build/hybrid_mp2.so` (psi4 world) and `build/cpp/hybrid_mp2_stages...so` (Einsums world).
   The top-level `CMakeLists.txt` absorbs the fiddly parts - module scanning off, the conda prefix for Einsums's dependency configs, and pointing the stage module's Python at the interpreter psi4's cache pins - so the two lines above are the whole incantation.
   `-DHYBRID_MP2_CPP_STAGES=OFF` builds the plugin alone; the python backend needs nothing else.

3. **Run**, with `einsums` importable and the directory above the package on `PYTHONPATH`:

   ```bash
   cd hybrid_mp2
   PYTHONPATH=/path/to/Einsums/build/lib psi4 -i input.dat
   ```

   The input runs psi4's own conventional MP2, then the plugin on the python backend, then on the cpp backend, and compares all three.
   The two stage backends agree bit for bit, because the C++ port emits the same einsums ops on the same values.

Backend selection is `set hybrid_mp2 stage_backend python|cpp`, and it is explicit: asking for `cpp` without having built it is an error rather than a silent Python fallback, because a fallback would report C++ timings that are not C++.

## The promotion workflow this template froze

The `cpp/` directory came from one command:

```bash
python -m einsums.stages promote hybrid_mp2/stages.py --out hybrid_mp2/cpp
```

which generated the contract header, the pybind bindings, the CMake build, the differential test, and a port skeleton whose body is the only hand-written C++ in it.
Regenerating after a contract change is the same command; promote refuses to overwrite anything you have edited, and never rewrites the skeleton or the build file at all.

For a method that starts as a *class* rather than free functions, the field extraction comes first:

```bash
python -m einsums.stages extract solver.py::MyMethod.build_t2
```

reports every `self` field the method touches and scaffolds the plan / numerics / finish split once you have written a cut spec saying what crosses.
The DLPNO example (`examples/dlpno/`) is the full-scale instance of both workflows.

## Differential test

```bash
PYTHONPATH=/path/to/Einsums/build/lib:.:hybrid_mp2/build/cpp \
  python -m pytest hybrid_mp2/cpp/tests -q
```

Synthetic inputs, no psi4 required, and a provenance assertion that pins that the cpp result really came from the compiled module.
The physics validation against psi4 lives in `input.dat`; this test only needs the two backends to be the same function.
